# Blender model integration

The browser viewer auto-loads the project-authored reference asset at `frontend/public/models/turbine.glb`. It can also load a local `.glb` model from the file picker; that file stays in the browser session and is not uploaded to the API. The project reference model is included in source control; arbitrary GLB/GTLF exports remain ignored.

The editable scene is `models/ge_6b03_reference.blend`, generated by `models/build_ge_6b03_reference.py`. Rebuild the scene, GLB, and render preview with `blender --background --python models/build_ge_6b03_reference.py`. See [the public-data review](GE_6B03_PUBLIC_DATA_REVIEW.md) for source links, which public dimensions are carried as metadata, and what remains approximate. The model is a conceptual reference visualization rather than an OEM drawing or dimensionally accurate assembly.

## Component mapping

The inspector has six stable semantic component IDs:

| Component | `component_id` value | Recognized object-name examples |
| --- | --- | --- |
| Inlet | `inlet` | `inlet`, `intake`, `air_entry` |
| Compressor | `compressor` | `compressor`, `comp_stage`, `compressor_casing` |
| Combustor | `combustor` | `combustor`, `combustion`, `combustion_chamber` |
| Turbine | `turbine` | `turbine`, `turbine_stage`, `turbine_casing` |
| Shaft | `shaft` | `shaft`, `rotor`, `spool` |
| Generator | `generator` | `generator`, `alternator` |

For dependable mapping, assign a Blender custom property named `component_id` to each component mesh or its parent object, using one of the exact IDs above. The loader also recognizes the listed object names and their parent names. Keep separately selectable component geometry under a parent per component; one merged mesh cannot provide a reliable per-component selection. Unmapped geometry remains visible but does not update the inspector when clicked.

## Part-level inspection

The part browser lists the exported mesh objects for the selected component. Keep physical parts as separate Blender objects when they need individual selection, isolation, or animation. The turbine stage vane proxies and bucket-casting proxies are exported as individual meshes; each instance has its own object name and stable part-browser entry. The proxy counts and shapes are illustrative.

Preserve metadata scope when exporting custom properties. A BHEL bucket-casting envelope/mass describes one bucket item and is attached to that individual proxy. A BHEL nozzle entry is a stage-level casting reference, so individual vane proxies expose it as related stage data with an explicit note; do not label it as a vane's own dimensions or mass. Geometry notes must remain visible beside public reference data.

## Viewer motion and navigation

The viewer supports orbit, pan, zoom, assembly explosion/isolation, and visual rotor motion that starts automatically when the Blender model loads; the user can pause it. The animation rotates the main shaft, compressor rotor rows, turbine bucket proxies, and turbine rotor wheels around the X axis at an illustrative rate. It is not tied to scenario data and must not be presented as actual RPM or operating motion. Keep stators and nozzle vanes stationary.

## Export and review

1. Keep the model centered around the turbine assembly and make the flow path visually clear. The viewer centers and scales the loaded scene automatically.
2. Use Blender's glTF 2.0 exporter and choose **GLB**. Enable custom properties / extras so `component_id` survives export.
3. Use standard metallic-roughness materials where possible. The viewer adds a restrained emissive highlight to selected component meshes.
4. Load the export in the browser and verify all six component chips and part-browser entries select the intended mesh and inspector metadata. Check bucket versus nozzle data scope, isolation, exploded view, rotor animation, and camera reset after orbiting/zooming.

This contract maps synthetic scenario state onto named visual groups. It does not make the model geometry or state an OEM-validated representation, a physical asset connection, or a real-time digital twin.
