# GitHub reuse review

Reviewed on 2 November 2026. Searches covered Brayton/gas-turbine solvers, turbine performance and synthetic time-series analysis, technical-document RAG, and agent orchestration. Repository activity dates below reflect the latest pushed commit observed during the review.

## Reviewed repositories and decisions

- [gbrandenbusch/brayton-analyzer](https://github.com/gbrandenbusch/brayton-analyzer) — MIT; pushed 26 May 2026. Uses CoolProp for a four-state simple-cycle calculation and sweeps. `brayton.py` has reusable equation references, but the repository also contains `.venv`/`__pycache__`, pins a plotting/thermo stack, and exposes no test suite. Reimplement a small validated cycle core; retain the equations as a cross-check only.
- [MarkZaki/jet_engine_brayton_cycle_analysis_and_sim](https://github.com/MarkZaki/jet_engine_brayton_cycle_analysis_and_sim) — MIT; pushed 26 March 2026. Modular solver/stage/model/performance/visualization layout, Streamlit/Plotly/NumPy/Pandas dependencies, and physics tests are useful patterns. Jet/turbofan/nozzle and flight-envelope scope is broader than TurbineIQ. Reuse structural ideas, not the aero-engine model.
- [MRod5/pyturb](https://github.com/MRod5/pyturb) — MIT; 84 stars, 16 forks, 8 open issues; last push 26 March 2023. Contains gas, combustion, atmosphere, and control-volume modules, with NumPy/SciPy dependencies and basic tests. README says it remains under development and packaging targets Python ≥3.5. Use as a concept reference, not a runtime dependency.
- [MohammadNafea85/gas-turbine-performance-analysis](https://github.com/MohammadNafea85/gas-turbine-performance-analysis) — MIT; pushed 18 June 2026. One-script analysis of a real UCI CCGT dataset; its fallback independently samples columns, and its README includes unsourced machine limits. Do not reuse its data, thresholds, or claims.
- [bludragon-ai/rae](https://github.com/bludragon-ai/rae) — MIT; pushed 18 June 2026. Streamlit + LangChain + Chroma/FAISS + sentence-transformers + pypdf; module boundaries cover settings, ingestion, cited RAG chain and tests. Requirements are broad and unpinned, and Python is ≥3.12. Reuse the source/page-citation pattern, keeping TurbineIQ retrieval local and light.
- [karineyasmin/weg_rag_project](https://github.com/karineyasmin/weg_rag_project) — pushed 14 January 2026. Technical-manual RAG with local/cloud fallback, but no license file or license metadata was found; the root also tracks `.env`. Python ≥3.13 and a large LangChain/Chroma/HuggingFace dependency set. Do not copy code.
- [langchain-ai/langgraph](https://github.com/langchain-ai/langgraph) — MIT; actively maintained, 44k+ stars, pushed 2 November 2026. Mature stateful orchestration, but adds LangChain Core, checkpoint, SDK, Pydantic and related packages. A small single-agent tool router is adequate for this MVP; revisit if durable workflows are later required.
- [sdv-dev/SDV](https://github.com/sdv-dev/SDV) — current license is Business Source License 1.1, not an OSI open-source license; its additional grant excludes synthetic-data-service use. It learns synthetic tables/sequences from input data and brings a large ML dependency tree. Do not adopt for this prototype.
- [arundo/adtk](https://github.com/arundo/adtk) — MPL-2.0; latest push 1 August 2024. Offers modular time-series detectors and aggregators; dependencies include NumPy, Pandas, Matplotlib, scikit-learn, and statsmodels. The broad stack and less-recent activity outweigh its value for a few explainable MVP checks.
- [parvjain190/Synthetic-Time-Series-Generator-For-Anomaly-Detection](https://github.com/parvjain190/Synthetic-Time-Series-Generator-For-Anomaly-Detection) — pushed 23 January 2026; notebook-only and no license file/metadata found. Describes trend/seasonality and point/contextual/collective anomalies, but is not turbine-specific. Use only the scenario categories as ideas, not code.
- [Shrinjita/synthetic-time-series-anomaly-detection](https://github.com/Shrinjita/synthetic-time-series-anomaly-detection) — last push 6 February 2025; notebook-only and no license file/metadata found. Generates hardware metrics with random anomalies and uses WMI/psutil, not a turbine model. No source reuse.

## Adoption recommendation

Build the thermodynamic core, physics-informed seeded scenarios, data-quality rules, offline synthetic twin, local retrieval, and constrained agent in TurbineIQ. Use repository examples to cross-check standard equations, test layout, source-citation structure, and model-versus-observation display. Use only clearly licensed third-party packages; do not import repository data or copy unlicensed notebook code. Every demo value remains synthetic or an explicitly stated modeling assumption—never an OEM rating or limit.

## Supplementary digital-twin review — 2 November 2026

This focused search was added after the user changed the original no-twin exclusion. It looked for demonstrators compatible with an offline, synthetic-only Streamlit prototype.

- [ankamteja/turbojet-digital-twin](https://github.com/ankamteja/turbojet-digital-twin) — MIT, 33 commits and 0 stars shown during review. Its four-stage turbojet twin uses a physics-informed surrogate, generated multi-engine dataset, tests, FastAPI/uvicorn, scikit-learn/pandas/NumPy, and a JavaScript/Three.js dashboard. The README also supports real telemetry through an API and estimates health/RUL. Reuse the conceptual separation of model state, observations, and time history; do not reuse code, since the machine and health-estimation scope differ and live telemetry is out of bounds.
- [ZandreC23/IoTSim-Virtual-Sensor-Network](https://github.com/ZandreC23/IoTSim-Virtual-Sensor-Network) — MIT; the README reports 21 API tests and a Python simulator → CSV → Streamlit dashboard architecture. It models generic temperature, humidity, and water-flow sensors and contains coursework assignment folders. Reuse the simple generated-feed/dashboard pattern only; no code is needed for TurbineIQ.
- [diawbirane10-lgtm/Digital_Twin_Li-ion_Batt_Packs](https://github.com/diawbirane10-lgtm/Digital_Twin_Li-ion_Batt_Packs) — GitHub showed 9 commits and no top-level license file in the repository listing. It has a Streamlit simulation workflow, a two-RC circuit model, and an extended Kalman filter, but is battery-specific and includes a separate telemetry workflow. Do not copy code; its distinction between synthetic simulation and measured-data analysis is a useful boundary pattern.
- [lazy-monster/dyon](https://github.com/lazy-monster/dyon) — PolyForm Noncommercial 1.0.0, a source-available license that reserves commercial use. It is a broad Python framework for live MQTT, storage, agents, and autonomous actions. Do not adopt it: its license and connected/action-oriented scope do not fit TurbineIQ.

### Digital-twin adoption decision

Implement the twin as a local synthetic asset record aligned to generated scenario samples. Show the timestamped model state, generated observation, residual screen, and provenance. Do not bind it to a physical turbine, add a real telemetry adapter, infer machine health, or issue control/maintenance actions. No third-party repository code or data was copied.
